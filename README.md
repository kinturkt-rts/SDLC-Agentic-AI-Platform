# SDLC Agentic AI Platform — Generated Applications

This repository is the **public catalog of target applications** produced by the SDLC Agentic AI Platform — an agentic pipeline that automates:

**requirements → architecture → database design → FastAPI implementation → tests → publish**

Each app is generated by specialist agents (product, architect, database, developer) running on **AWS Strands** and **Amazon Bedrock**, then published here for review and reuse. The **platform source** (agents, orchestration, `run-sdlc.ps1`, pipeline scripts) lives in a separate private monorepo; **this repo contains only generated apps and their design artifacts**.

---

## Repository layout

```
SDLC-Agentic-AI-Platform/
├── README.md                 # This file — app index and conventions
├── <app-name>/               # Generated FastAPI service (one folder per app)
│   ├── app/                  # API routes, models, security
│   ├── db/sql/               # Migrations and seed scripts
│   ├── tests/                # Pytest suite
│   ├── ui/                   # Streamlit UI (when applicable)
│   ├── requirements.txt
│   ├── .env.example          # Copy to .env — never commit secrets
│   └── README.md             # App-specific setup and API docs
├── docs/
│   ├── PRD/                  # Product requirements (<app-name>.md)
│   └── design/               # Architecture & API design (<app-name>.md)
└── agents/pipeline/          # Pipeline handoff JSON (optional, internal metadata)
```

**Naming:** App folders use kebab-case (e.g. `training-compliance`). Each app is self-contained — clone this repo, `cd` into one folder, and run it independently.

## How apps are generated

| Step | Agent | Output in this repo |
|------|-------|---------------------|
| 1 | **product-agent** | `docs/PRD/<app>.md` |
| 2 | **architect-agent** | `docs/design/<app>.md`, architecture diagram |
| 3 | **database-agent** | `<app>/db/sql/*.sql`, `db/HANDOFF.md` |
| 4 | **developer-agent** | `<app>/` FastAPI app, tests, UI, `README.md` |
| 5 | **devops-agent** | Git branch + pull request (GitHub MCP or git) |
| 6 | **qa-agent** | Local pytest + PR review comment |

## Run an app locally

Every app follows the same pattern. Example for **training-compliance**:

### Prerequisites

- Python 3.12+
- PostgreSQL (local or RDS)

### Setup

```bash
git clone https://github.com/kinturkt-rts/SDLC-Agentic-AI-Platform.git
cd SDLC-Agentic-AI-Platform/training-compliance
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env               # Edit DATABASE_URL, JWT_SECRET_KEY, etc.
```

### Database

Apply SQL scripts in order under `db/sql/`, then seed:

```bash
# Example with psql
psql "$DATABASE_URL" -f db/sql/001_create_departments_jobroles.sql
# ... remaining migrations in numeric order ...
psql "$DATABASE_URL" -f db/sql/011_seed.sql
```

See each app's `README.md` and `db/HANDOFF.md` for exact steps.

### Start API + UI

```bash
# Terminal 1 — API
uvicorn app.main:app --reload --port 8000

# Terminal 2 — Streamlit UI (if present)
pip install -r ui/requirements.txt
streamlit run ui/streamlit_app.py
```

Health check: `GET http://localhost:8000/health`

### Tests

```bash
pytest
```

| Layer | Technology |

## Contributing / adding apps

Apps are **not hand-edited in this repo** under normal workflow. They are generated by the SDLC pipeline and published via:

1. Feature branch (e.g. `training-compliance` or `sdlc/<app>`)
2. Pull request into `main`
3. Review, merge, update the app table in this README

To change a generated app after merge, update the platform pipeline or open a PR against the app's folder.

---

## Security

- **Never commit** `.env`, credentials, or API keys.
- Use `.env.example` as a template only.
- Seed scripts use dev passwords; rotate before any real deployment.
